# Alaap incoming-call test

For persistent registration, fact confirmation, Supabase setup, agricultural source collection and local model experiments, see [the implementation guide](../docs/IMPLEMENTATION.md). The authenticated operator console is http://127.0.0.1:8765/operator.html. Select a consented case there before opening the telephone tester to enable backend tools.

Requires Node.js 22 or newer and Chrome or Edge. Run `npm install` once for the Vertex AI voice bridge.

1. In this folder run `node server.mjs`, then open http://127.0.0.1:8765.
2. Enter the provider access token and SIP password. Use the extension and realm supplied by your provider. Credentials stay in memory and the secret fields clear after connecting. Do not save them in browser password storage.
3. Select **Check microphone permission and devices**, allow microphone access, and select your headset. This briefly opens the microphone and immediately releases it.
4. Select **Enable automatic answering**, then **Connect**. Wait for **Registered**. Leave this page open and the laptop awake; keep this test window in the foreground for the initial test.
5. Call **your provider test DID** from a separate phone. Speak in both directions using headphones. If playback is blocked, click **Play incoming audio**.
6. End the first call from the phone, the second with **Hang up**, and the third from the phone. Verify each subsequent call succeeds without reconnecting. Increasing counters prove packet traffic, not intelligible speech.
7. Download the redacted log and note which calls had intelligible audio both ways. Use **Disconnect** when finished; reconnect requires entering credentials again.

Run automated checks with `node --test`. The server binds only to the laptop's loopback address. Audio travels over WebRTC. The WebSocket carries signalling only.

### Realtime AI test

For the free, local comparison, use **Whisper comparison (optional)** instead. Install the worker with `uv venv --python 3.11 .bangla-venv` and `uv pip install --python .bangla-venv/Scripts/python.exe faster-whisper edge-tts indic-transliteration`. Run `.bangla-venv/Scripts/python.exe -u bangla.py` in one terminal and `node server.mjs` in another. The first worker launch downloads both models.

The test expects `bangla-reply.mp3` in this folder. To regenerate the fixed reply from PowerShell, run `.bangla-venv/Scripts/edge-tts.exe --voice bn-BD-NabanitaNeural --text "দাগগুলো পাতার কোন অংশে দেখা যাচ্ছে?" --write-media bangla-reply.mp3`. This sends only the fixed reply text to the synthesis service during setup. Caller audio is processed locally in memory.

Once the call connects, click **Capture Bangla speech**, have the caller speak one short sentence, then click **Finish utterance**. Repeat with a Chittagonian speaker. Compare crop names, symptoms, and numbers in both transcripts. The displayed reply timing measures capture end to local playback start. Ask the caller when they actually hear it.

For hands-free turns, install `indic-transliteration` in the same environment and run `.bangla-venv/Scripts/python.exe generate-bangla-prompts.py` once. This generates the fixed questions from `bangla-prompts.json`; it sends no caller content. Click **Start hands-free Bangla** once on a connected call. The regional model runs after about 600 ms of quiet. The page shows the raw, lightly cleaned, and Latin-script text. It asks a Bangla question about the crop, symptom, or timing based on the current call, then listens again. Wait until **Listening** before the next sentence. **Stop Bangla test** or hangup releases the audio connection.

With the caller's permission, check **Save next turn for QA** before speaking. The checkbox clears when that turn is selected. The exact WAV passed to the regional model and a matching JSON report are written to `qa/captures/`, which is excluded from Git. The page reports the saved filename. Use it to compare the captured speech, transcript, and spoken follow-up.

### Vertex AI voice

### Live operator workspace

Open `http://127.0.0.1:8765/workspace.html`, or select a case in the operator console and open its workspace. Use **Connection** to configure telephone access, answer a call, then start AI voice. The existing `/` tester remains available for diagnostics.

Use **Choose registration case** directly in the workspace before starting Vertex AI. Select an existing open case or create one after obtaining the caller's storage consent. This attaches the case without reloading or disconnecting telephone media; changing a case stops the previous AI session. New registrations and synthetic cases default to Vertex. Starting without a case opens this picker rather than leaving the operator at an unexplained block.

Sign in directly in the workspace with the email code/link. Verified operator sessions are retained for seven days in an HttpOnly cookie; access and refresh tokens stay encrypted in the ignored local `.secrets/operator-sessions` file. The server renews access using Supabase's [refresh-session API](https://supabase.com/docs/reference/javascript/auth-refreshsession), checks operator permission on renewal, and restores sessions after restart. Signing out removes the saved local session and disconnects the telephone. A session without a refresh token requires sign-in again when its access token expires.

Set `ALAAP_ACCESS_TOKEN`, `ALAAP_SIP_EXTENSION`, `ALAAP_SIP_DOMAIN` and `ALAAP_SIP_PASSWORD` in `.env.local` for automatic telephone registration after sign-in. The authenticated same-origin setup endpoint supplies credentials only to the telephone client, which does not store them in browser storage. Automatic registration does not enable automatic answering or bypass microphone permissions. An expired/rejected provider credential still needs replacement; **Connection** retains the manual fallback. Use one workspace tab for the shared extension.

The dark workspace uses a green/red gradient orb with warm yellow undertones. Its outline responds to actual caller and playback audio. Transcript highlights match exact recorded source turns; proposals remain distinct from confirmed or corrected fields. Authenticated case snapshots and tool events populate the profile, pipeline and evidence inspector. Weather and the local product dictionary are explicitly unavailable. Decision explanations describe backend results, not private model reasoning.

Layout references inspected through Mobbin: [Mindtrip voice](https://mobbin.com/screens/2a51b384-1642-4e16-959d-cdfc74b09455) and [ChatGPT source inspector](https://mobbin.com/screens/88d5e839-cf2b-447b-887c-a4beeead8040). The implementation uses original HTML/CSS and no added dependencies. Keyboard tabs, reduced motion and responsive stacking are supported; live phone and visual device verification remain required.

### Vertex configuration

Copy `.env.example` to `.env.local` and set your Google Cloud project, service-account file path (or use Application Default Credentials), and the TURN username/password supplied by Alaap. Do not commit that environment file or the service-account JSON. The default voice model is `gemini-live-2.5-flash-native-audio` in `us-central1`; the project needs Vertex AI permissions, billing, and quota. For user credentials, leave `GOOGLE_APPLICATION_CREDENTIALS` unset and run `gcloud auth application-default login` and `gcloud auth application-default set-quota-project YOUR_PROJECT_ID`.

Alaap access tokens and SIP passwords can be entered manually in **Connection**, or loaded automatically from server configuration after operator sign-in. TURN credentials are loaded by the local server and returned only to same-origin requests from the tester. They are required for the relay-only telephone media connection.

Vertex startup waits for actual generated audio before showing connected. Capacity errors and startup timeouts trigger at most three attempts: the configured region, `us-east1`, then `us-west1`, removing duplicates, with two- and four-second delays. These regions use the same configured project, credentials, model, and intake tools. This handles intermittent regional capacity; it does not add project quota. Permission and billing errors stop immediately. Established conversations are never automatically restarted or replayed. Closing AI voice cancels startup. Other projects are not used without verified access and billing.

For a synthetic test using the separate Gemini Developer API, set `GEMINI_API_KEY` on the local server and optionally `GEMINI_LIVE_MODEL` (default `gemini-2.5-flash-native-audio-preview-12-2025`). During a test call, select **Use Gemini Developer API for a synthetic test only**, then start AI voice. The key never goes to the browser. To test saved registration, sign in at `/operator.html`, mark the new case as **Synthetic registration test**, confirm storage consent, create it and open its telephone link. Use fictional details only. The backend checks the stored synthetic marker and operator session; a query flag cannot authorize a real farmer case for the free API. Free-tier content may be used to improve Google products. Vertex remains the default for real farmer cases; Developer API quota errors do not rotate keys or regions.

Case-bound voice opens with **আসসালামু আলাইকুম**, identifies itself as AI, and asks for service/storage consent before preferred name, approximate location and associated mobile number. Pending values require spoken read-back and a later explicit confirmation. Age is optional. The backend refuses guidance retrieval until registration is complete. Without a selected case, the page states that profiling is off; ordinary voice startup requires a case, while explicit synthetic voice-only tests remain available without persistence.

Live tools bind proposals and confirmations to backend-recorded turns; the model does not need to manufacture turn or batch IDs. Read-back still requires all values and completed playback. Phone read-back accepts equivalent local/international formats and Bengali digits while comparing the complete number. Common explicit replies use a fast local check. Other replies are interpreted in context through a structured Vertex request (`GEMINI_EXTRACT_MODEL`, default `gemini-2.5-flash`), using only the current read-back, proposed fields and caller reply. The result distinguishes agreement to every value, refusal, correction and uncertainty; only grounded, sufficiently confident agreement can confirm a profile. Corrections remain pending for a new proposal and read-back. Unavailable interpretation or an unclear reply triggers natural clarification, never an assumed yes. This extra request has a three-second timeout and can add reply latency. It does not guarantee accuracy across dialects or incorrect speech transcripts. Interrupted output cannot acknowledge a delayed read-back. Failed tool steps show a safe reason in the activity panel; a model saying “confirmed” is never proof of a saved profile.

When a location proposal contains a bad transcript but the caller later explicitly restates the place, confirmation can recover that restatement if its exact location also appears in a delivered read-back before the agreement. A bounded Vertex extraction request selects the source; the backend verifies both quotes and turn order, replaces the proposal and applies the normal confirmation checks. A yes alone cannot rewrite a location. Missing evidence returns an actionable recovery instruction instead of repeatedly asking for agreement to a mismatched value. This recovery currently covers a single pending profile location and may add up to three seconds; it does not provide general place-name or dialect normalization.

Names and locations also support semantic read-back comparison when literal matching fails: Bangla/English transliteration, location aliases, grammatical inflection and reordered district/subdistrict wording can express the same value. A bounded Vertex comparison must cover every unmatched name/location with high confidence and exact evidence from the delivered read-back. The backend binds this evidence to the active batch and turn; it cannot alter the proposed values or confirm them without a later caller agreement. Phone, age and consent cannot use this fallback. Results are cached for each batch/playback, including unavailable results. A failed comparison stays unconfirmed. This adds up to three seconds on mismatches and is still model interpretation, not guaranteed identity or location verification.

For responsive turn-taking, Gemini 2.5 Developer test voice disables extra model thinking. The voice sessions use a 500 ms silence window with 120 ms speech prefix padding, and the browser uploads 32 ms PCM blocks at 16 kHz. This trades tolerance for longer mid-sentence pauses against reply speed; test natural farmer speech before deployment. It does not change the backend fact-confirmation or evidence requirements.

The native-audio session enables proactive audio and low start-of-speech sensitivity to reduce responses to irrelevant sounds. Vertex receives a `bn-BD` input transcription hint, accepted in a live startup check; this guides recognition but does not guarantee the language or accuracy of every caption. The separate Developer API test path retains its existing transcription setup. Bangla remains the conversation language unless the caller clearly requests otherwise. Input audio passes through 100 Hz high-pass and 7 kHz low-pass filters. These filters reduce rumble and out-of-band noise; they are not a cough classifier or speaker-isolation system.

The backend rejects noise-only captions, corrupted characters, obvious repetition and unexpected script drift before proposing or confirming facts. Roman Bangla and English code-switching remain allowed. A rejected turn cannot fall back to an older caller reply. Noise-marked confirmations require a repeat. The operator view shows quality warnings and a reply timer rather than treating these captions as confirmed information. Script checks are heuristics, not reliable language identification or an ASR accuracy score.

After a caller transcript, a four-second warning indicates a slow response; a twelve-second missing-audio deadline stops AI voice while keeping telephone media connected. During registration, a delivered question with no clear reply triggers one gentle repeat after twenty seconds and ends AI voice after prolonged silence. All timers are cleared on stop. Slow requests never count as consent or confirmation. End-to-end delay and real noisy telephone speech still require live validation.

Restart `node server.mjs` after changing configuration. With the caller's agreement, click **Start AI voice** during a connected phone call. Caller audio streams through the local `/vertex` WebSocket to Google Cloud, and generated speech is sent back to the phone. The main **Live transcript from Vertex AI** panel displays caller and AI captions directly from Vertex. Local Whisper results are kept separately under the collapsed **Whisper comparison (optional)** section. **Stop AI voice** restores the laptop microphone; hanging up closes the Vertex session. One AI session is allowed at a time, with a ten-minute test limit. No caller audio or captions are saved by this bridge. Google Cloud usage is billed to the selected project; vendor retention is separate from local storage.

This is an experimental voice conversation. Case-linked sessions can propose and confirm facts, retrieve approved evidence and record referral requests. Reviewed agricultural content, actual expert appointments and SMS are not supplied automatically. Do not treat output as validated agricultural advice. Dialect accuracy, interruptions and phone-to-phone response delay need live testing.

If registration fails, verify token expiry, extension/password, the supplied realm, and possible use of the shared test extension by someone else. The realm need not resolve locally when an explicit SIP proxy routes registration. Do not substitute the proxy IP as the realm without provider confirmation or protocol evidence.

If registered but the DID never rings, ask the provider to verify DID-to-extension routing. If ICE fails or counters remain zero, inspect TURN/network access before changing voice services. Browser permission denial is recovered by allowing the microphone for this local site, then calling again. Disconnect/reconnect tests temporarily stop the client receiving calls. No automatic reconnect is implemented.

The included TURN configuration comes from the supplied guide and needs a real media test. The shared test account may conflict with other registrations. This is a single-call diagnostic client, not a production telephone service.
